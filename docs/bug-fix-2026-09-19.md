# imap-mcp-server 发送邮件参数验证 Bug 修复指南 / Fix Guide for the Send-Email Parameter Validation Bug

## Bug 描述 / Bug description

**imap-mcp-server** 是一个用于 MCP (Model Context Protocol) 的 IMAP/SMTP 邮件服务器插件。在调用 `imap_send_email` 等发送邮件相关工具时，`to`（收件人）参数始终报参数验证错误，导致无法发送邮件。

**imap-mcp-server** is an IMAP/SMTP email server plugin for MCP (Model Context Protocol). When calling email-sending tools such as `imap_send_email`, the `to` (recipient) parameter always reports a parameter-validation error, making it impossible to send email.

---

## 影响范围 / Impact scope

- **工具 / Tools**：`imap_send_email`、`imap_save_draft`、`imap_forward_email` 等所有需要填写收件人的工具 / all tools that require a recipient.
- **参数 / Parameters**：`to`、`cc`、`bcc` 地址列表参数 / the address-list parameters.
- **读取功能 / Read features**：不受影响，读取、搜索、移动等 IMAP 操作正常 / unaffected; IMAP operations such as reading, searching and moving work normally.

---

## 错误现象 / Error symptom

调用发送邮件工具时，返回以下错误 / calling a send-email tool returns:

```
MCP error -32602: Input validation error: Invalid arguments for tool imap_send_email: Invalid input at to
```

无论 `to` 参数传什么格式都报错 / the error occurs regardless of the format passed to `to`：

- 纯字符串 / plain string：`"user@example.com"`
- 字符串数组 / string array：`["user@example.com"]`
- 带名字格式 / named format：`"Name <user@example.com>"`
- 对象数组 / object array：`[{"email": "user@example.com"}]`

---

## 原因分析 / Root-cause analysis

### 根本原因 / Root cause

`addressList()` 工具函数使用了 `z.preprocess` + `z.union([z.string(), z.array(z.string())])` 的 Zod Schema 组合。

The `addressList()` helper uses a Zod schema combination of `z.preprocess` + `z.union([z.string(), z.array(z.string())])`.

**问题代码位置 / Problem code location**：`dist/index.js` 约第 2766 行 / around line 2766

```javascript
var addressList = (field, description) => z2.preprocess(
  (value) => parseSerializedArray(value, field),
  z2.union([z2.string(), z2.array(z2.string())])
).describe(description);
```

### 为什么会出问题 / Why it happens

MCP 框架在注册工具时，会把 Zod Schema 转换为 JSON Schema，用于客户端参数验证。

When registering a tool, the MCP framework converts the Zod schema into JSON Schema for client-side parameter validation.

- `z.preprocess` 是一个运行时预处理装饰器，没有对应的 JSON Schema 类型 / `z.preprocess` is a runtime pre-processing decorator with no JSON Schema counterpart.
- `z.union([z.string(), z.array(z.string())])` 转换为 JSON Schema 是 `anyOf` 结构 / the union converts to an `anyOf` structure in JSON Schema.
- 两者组合后，MCP 框架生成的 JSON Schema 中，`to` 参数**丢失了 `type` 字段** / combined, the `to` parameter **loses its `type` field** in the JSON Schema generated by the MCP framework.

客户端拿到没有 `type` 定义的参数 schema，在验证时认为参数格式不合法，直接报 `Invalid input at to` 错误。/ A client receiving a parameter schema without a `type` definition considers the parameter invalid and reports `Invalid input at to`.

---

## 修复方法 / Fix approach

### 方案 / Approach：简化 Schema，去掉 `z.preprocess` + `z.union` 的组合 / simplify the schema by removing the `z.preprocess` + `z.union` combination

把所有使用 `addressList()` 的参数改成简单的 `z.string()`，确保 JSON Schema 里有明确的 `type: "string"` 定义。/ Replace every parameter that uses `addressList()` with a plain `z.string()`, so the JSON Schema always carries an explicit `type: "string"`.

### 2. 修改 `to` 参数定义 / 2. Change the `to` parameter definition

搜索 `addressList("to",`，把所有出现的地方替换为 `z2.string().describe(` / search for `addressList("to",` and replace every occurrence with `z2.string().describe(`.

**修改前 / Before**（约第 3475 行，imap_send_email / around line 3475, imap_send_email）：


**注意 / Note**：同时去掉后面的 `.nonoptional()`，因为 `z.string()` 默认就是必需的。/ also remove the trailing `.nonoptional()`, because `z.string()` is required by default.

## 备注 / Notes

### 为什么不直接修改 `addressList` 函数？/ Why not modify the `addressList` function itself?

你可能会想：直接把 `addressList` 函数里的 `z.union(...)` 改成 `z.any()` 不就行了吗？/ you may wonder: why not just change the `z.union(...)` inside `addressList` to `z.any()`?

**不推荐 / Not recommended**：

- `z.any()` 在某些 MCP 框架的 JSON Schema 转换中可能有兼容性问题 / `z.any()` may have compatibility issues in some MCP frameworks' JSON Schema conversion.
- 改成 `z.string()` 更标准、更稳定 / plain `z.string()` is more standard and stable.
- 虽然描述里说支持数组，但实际使用中传单个邮箱地址是最常见的场景 / although the description mentions array support, a single address is the most common real-world usage.
