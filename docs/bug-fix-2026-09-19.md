# imap-mcp-server 发送邮件参数验证 Bug 修复指南

## Bug 描述

**imap-mcp-server** 是一个用于 MCP (Model Context Protocol) 的 IMAP/SMTP 邮件服务器插件。在调用 `imap_send_email` 等发送邮件相关工具时，`to`（收件人）参数始终报参数验证错误，导致无法发送邮件。

---

## 影响范围

- **工具**：`imap_send_email`、`imap_save_draft`、`imap_forward_email` 等所有需要填写收件人的工具
- **参数**：`to`、`cc`、`bcc` 地址列表参数
- **读取功能**：不受影响，读取、搜索、移动等 IMAP 操作正常

---

## 错误现象

调用发送邮件工具时，返回以下错误：

```
MCP error -32602: Input validation error: Invalid arguments for tool imap_send_email: Invalid input at to
```

无论 `to` 参数传什么格式都报错：
- 纯字符串：`"user@example.com"`
- 字符串数组：`["user@example.com"]`
- 带名字格式：`"Name <user@example.com>"`
- 对象数组：`[{"email": "user@example.com"}]`

---

## 原因分析

### 根本原因

`addressList()` 工具函数使用了 `z.preprocess` + `z.union([z.string(), z.array(z.string())])` 的 Zod Schema 组合。

**问题代码位置**：`dist/index.js` 约第 2766 行

```javascript
var addressList = (field, description) => z2.preprocess(
  (value) => parseSerializedArray(value, field),
  z2.union([z2.string(), z2.array(z2.string())])
).describe(description);
```

### 为什么会出问题

MCP 框架在注册工具时，会把 Zod Schema 转换为 JSON Schema，用于客户端参数验证。

- `z.preprocess` 是一个运行时预处理装饰器，没有对应的 JSON Schema 类型
- `z.union([z.string(), z.array(z.string())])` 转换为 JSON Schema 是 `anyOf` 结构
- 两者组合后，MCP 框架生成的 JSON Schema 中，`to` 参数**丢失了 `type` 字段**

客户端拿到没有 `type` 定义的参数 schema，在验证时认为参数格式不合法，直接报 `Invalid input at to` 错误。

---

## 修复方法

### 方案：简化 Schema，去掉 `z.preprocess` + `z.union` 的组合

把所有使用 `addressList()` 的参数改成简单的 `z.string()`，确保 JSON Schema 里有明确的 `type: "string"` 定义。

---

## 修改步骤

### 1. 定位文件

找到 imap-mcp-server 的安装目录，通常在：
```
<node安装目录>/node_modules/imap-mcp-server/dist/index.js
```

### 2. 修改 `to` 参数定义

搜索 `addressList("to",`，把所有出现的地方替换为 `z2.string().describe(`

**修改前**（约第 3475 行，imap_send_email）：
```javascript
to: addressList("to", 'Recipient email address(es). Either an array of addresses or a single comma-separated string; both accept "Name <addr@example.com>" form.').nonoptional(),
```

**修改后**：
```javascript
to: z2.string().describe('Recipient email address(es). Either an array of addresses or a single comma-separated string; both accept "Name <addr@example.com>" form.'),
```

**注意**：同时去掉后面的 `.nonoptional()`，因为 `z.string()` 默认就是必需的。

### 3. 同样修改其他使用 `addressList` 的参数

搜索所有 `addressList(` 的调用，替换为 `z2.string()`：

| 工具 | 参数 | 修改 |
|---|---|---|
| `imap_send_email` | `to` | `addressList("to", ...).nonoptional()` → `z2.string().describe(...)` |
| `imap_send_email` | `cc` | `addressList("cc", ...).optional()` → `z2.string().describe(...).optional()` |
| `imap_save_draft` | `to` | 同上 |
| `imap_save_draft` | `cc` | 同上 |
| `imap_forward_email` | `to` | 同上 |

### 4. 批量替换脚本（PowerShell）

如果你用的是 Windows，可以用以下脚本快速替换：

```powershell
$file = "<imap-mcp-server 完整路径>/dist/index.js"
$content = [IO.File]::ReadAllText($file)

# 把 addressList("xxx", 替换为 z2.string().describe(
$content = $content -replace 'addressList\("(\w+)",', 'z2.string().describe('

# 去掉 .nonoptional()
$content = $content -replace '\)\.nonoptional\(\)', ')'

[IO.File]::WriteAllText($file, $content)
```

## 验证方法

### 1. 重启 MCP 服务

修改完成后，重启 MCP 服务（或重启客户端应用），让代码生效。

### 2. 确认 Schema 已更新

调用工具前，先通过 MCP 客户端查看 `imap_send_email` 的参数 schema，确认 `to` 参数有：
```json
{
  "type": "string",
  "description": "..."
}
```

### 3. 测试发送邮件

```json
{
  "to": "recipient@example.com",
  "subject": "测试",
  "text": "这是一封测试邮件"
}
```

如果返回 `success: true`，说明修复成功。

## 备注

### 为什么不直接修改 `addressList` 函数？

你可能会想：直接把 `addressList` 函数里的 `z.union(...)` 改成 `z.any()` 不就行了吗？

**不推荐**：
- `z.any()` 在某些 MCP 框架的 JSON Schema 转换中可能有兼容性问题
- 改成 `z.string()` 更标准、更稳定
- 虽然描述里说支持数组，但实际使用中传单个邮箱地址是最常见的场景
